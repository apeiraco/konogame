# 前端体验

状态：提案，2026-10-17。当前仓库尚无图形前端、启动流程或持久任务 API。下述交互模型与技术候选属于后续设计，不代表已实现能力。

结合[当前架构](../001-ARCHITECTURE.md)、[Workspace 提案](002-WORKSPACE-CONFIGURATION.md)、[发现提案](003-GAME-DISCOVERY.md)和[迭代计划](001-INITIAL-ITERATIONS.md)阅读。

## 从历史设计继承的意图

保留共享前端、管理与游玩两种体验、手柄导航、封面、非阻塞任务以及任务完成后的实用操作。[旧前端设计](../archive/004-FRONTEND-UI.md)描述了电视体验；[原始讨论](../archive/100-INIT-DISCUSSION-BACKUP.md)第 10–14 回合讨论了共享客户端、输入与任务通知。

把固定库版本和全面禁止原生 DOM 焦点等规则调整为可验证的交互约定。动画不能掌管导航或任务状态。跨宿主共享 UI 仍需要各平台的权限处理、打包与测试。

## 已实现 CLI 基础

[ADR 0002](../adr/0002-WORKSPACE-TOML-AND-TOOLING.md) 采纳 Optique 命令解析器与 `@clack/prompts` TTY 辅助。TTY 会话无命令时提供菜单，可补问缺失参数。交互优先级为参数 > 环境 > TTY；`--non-interactive`、`--interactive=false`、`INTERACTIVE=false` 禁用提示。JSON/非 TTY 执行不提示，取消不写入。`workspace rename <root> <id> <name>` 是专用统一名流程，保留注释、UUID 引用与布局，并报告冲突/恢复要求。CLI 已支持只读 `game discover` JSON 和所选 `game import --yes` 录入，以及针对 pending journal 的显式 `workspace recover-import --yes`。[ADR 0004](../adr/0004-LOCAL-DISCOVERY-AND-INJECTION.md)记录当前范围；图形编辑/审核仍为提案，未实现启动入口发现。

## 两种模式，共享操作

| 模式 | 主要体验 | 共享行为 |
| --- | --- | --- |
| 管理模式 | 鼠标与键盘、详细列表、发现审核、配置差异、批量选择和诊断。 | 同一套游戏身份、应用命令、校验、能力可用性与任务结果。 |
| 游玩模式 | 清晰的大尺寸目标、手柄导航、聚焦的游戏库、安装实例/启动入口选择和快捷操作。 | 同一套游戏身份、应用命令、校验、能力可用性与任务结果。 |

切换模式时保留选中的 Game 和相关上下文。复杂编辑可通过清晰入口转到管理模式，无需把所有表单都复制为电视浮层。触摸布局在后续围绕这些流程适配。

导航围绕游戏库、单个游戏的资产与操作、发现、任务和设置组织。Adapter 选项放在相关操作的设置与诊断中。用户保存存档或选择安装实例时，不应必须先理解内部包结构。

## 根据能力呈现操作

应用服务应根据选中的 Game、Installation、主机和有效配置提供操作可用性。建议区分可用、需要配置、不支持、暂时不可用，并给出可采取行动的说明。仅声明了 Port 并不代表操作可用。

UI 请求 Feature 并呈现应用结果，不自行选择厂商工具或复制协商规则。详细视图可以解释 Binding Plan，包括不兼容的显式偏好；日常操作视图则说明缺少什么，以及用户如何处理。

例如，filesystem 存储可以提供 Artifact 存储而不提供历史浏览。恢复配置修订、导入存档和恢复资产快照需要不同的用词与预览。Binding Plan 用于确定实现，不能代替完整的文件改动预览，也不保证回滚。

## 复用与宿主边界

共享面向领域的类型、应用客户端接口、视图模型、设计组件和输入动作。文件系统访问、进程启动、凭据、通知和窗口控制通过宿主 Adapter 提供。可复用 UI 不直接依赖 Node 或桌面壳的全局对象。

浏览器与桌面客户端通过明确的宿主/传输边界访问同一应用服务。现有 CLI 仍可不依赖 Daemon 在本地运行。当前 Daemon 只有 localhost 健康检查与计划查询原型，尚不是任务服务，也不具备远程部署能力。

明确显示安装实例、路径和运行任务属于哪台主机。远程浏览器中输入的路径，只有在含义明确时才解释为执行主机路径；浏览器选中的本地文件不能静默当作远程服务路径。提供远程操作前，需要分别决定鉴权、授权的主机访问和远程部署方式。

先覆盖 Windows 工作流与一种本地客户端。浏览器、桌面壳和未来移动端打包作为宿主选项，在合适场景提供响应式布局，不承诺原生能力完全一致或无需平台适配。

## 首批用户流程

1. **配置 Workspace：** 查看有效值及来源，编辑记录，校验，查看语义差异，再基于原修订应用。发生冲突时返回审核。可选配置历史复用相同的校验与预览流程。
2. **发现游戏：** 选择范围与允许的来源，查看逐步返回的候选和证据，处理冲突或忽略候选，然后审核拟写入 Workspace 的改动再录入。打开应用不会开始扫描。
3. **使用游戏资产：** 选择支持的操作，查看相关条件与影响，启动操作并跟踪任务。存储不隐含历史版本或复制能力。
4. **游玩游戏：** 选择 Installation 与启动入口，查看未满足的前提，并在启动契约实现后显式启动。下载、导入或补丁任务成功后可以推荐启动，不自动打开游戏。

这些流程可先通过夹具演示。夹具必须明确标注不可用或模拟的行为，不能据此认定后端已支持。

## 键盘、手柄与焦点

使用语义化控件、合理的 Tab 顺序、可见焦点和可访问名称。复合控件内部采用适合该控件的键盘模式；受控焦点可以使用 roving `tabindex` 或 `aria-activedescendant`，取代历史文档中禁止 `tabIndex` 的要求。参见 [W3C 键盘交互指南](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/)，于 2026-10-17 核对。

把手柄输入映射为导航、确认、返回和上下文操作，显示对应设备的按键提示，并允许配置操作习惯。返回应先关闭当前菜单/对话框，或沿应用流程返回，不能直接无条件调用浏览器历史。避免把所有手柄事件直接映射成任意 DOM 点击。

焦点、选中状态与动画分别管理。筛选和虚拟化列表保留稳定条目标识；关闭对话框、切换页面或移除条目后，恢复到合理的焦点目标。方向导航、滚动与虚拟化需要协同。通知不抢焦点，输入重复也不应意外多次提交操作。

主游戏库、游戏详情、任务查看和主要游玩操作应能通过键盘或手柄完成。详细文本输入可使用键盘或宿主提供的输入方式。在宣称无障碍支持前，除自动交互检查外，还需验证真实手柄和辅助技术。

## 任务中心与通知

任务状态由应用/执行主机管理。建议的任务模型包括稳定任务 ID、操作与目标、主机、生命周期状态、进度、取消支持、结果和结构化错误。区分已请求取消与确认取消，并呈现部分生效的改动。总量未知时显示当前阶段或已处理数量，不编造百分比。

任务中心保留可查看的进行中任务与失败记录；Toast 提供摘要和可选操作，不作为唯一记录。完成后可按场景提供查看结果、检查日志或启动。暂停、续接与重试取决于操作契约；没有明确的恢复或幂等策略时，不自动重试修改操作。

UI 观察任务，不拥有任务生命周期。本地前台 CLI 操作仍可随其进程结束。窗口关闭后继续工作，需要具有明确生命周期策略的执行主机。重新连接时应恢复任务快照并协调后续事件，避免重复执行；事件序列与请求身份需要在实现前形成契约。主机重启后的持久恢复属于后续独立保证。

首个客户端可以支持前台任务，并显示实际生命周期限制。仅有任务抽屉不能意味着支持后台执行、事件传输、记录保留和持久恢复。

## 视觉与技术候选

TypeScript UI、React、Vite、TanStack 工具以及 shadcn/ui、Tailwind 等组件/样式方案属于候选，不是固定依赖清单。实现时结合首个交互切片、宿主限制和键盘/手柄验证选择仍在维护的版本与库。无论选哪种库，都需要明确 UI 状态、服务端状态、传输与焦点管理的归属。

过渡动画用来表达上下文连续性，同时保持即时输入反馈。尊重减少动态效果的偏好。如果选择 Motion，可以使用其文档中的减少动画控制，但不能让操作正确性或焦点恢复依赖动画完成。参见 [Motion 无障碍指南](https://motion.dev/docs/react-accessibility)，于 2026-10-17 核对。

封面保留来源、原图、派生版本、裁切选择以及可用的缺图状态，并限制下载与缓存开销。可选 AI 增强产生带来源记录和明确标识的派生图，不视为缺失细节的无损恢复，也不能静默替换原图。

## 首次交付与待决问题

先演示 Workspace 查看/编辑预览、发现审核、能力可用性以及前台任务反馈的管理视图。建立小型共享应用客户端边界，尚无服务的部分使用夹具；随着契约稳定逐项接入真实服务。随后验证游玩模式的游戏库/详情流程及手柄焦点。桌面后台运行、远程客户端与移动端分开推进。

扩展范围前，需要确定首个宿主与打包方式、应用客户端传输、任务生命周期和事件契约、UI 状态归属、焦点与虚拟化策略，以及 Extension 如何贡献 UI。Feature 操作描述可以表达可用性，但不要求所有领域流程都塞进自动生成的表单。已采纳的架构选择进入 ADR。

## 验收目标

- 管理与游玩视图使用相同的应用结果，并显示一致的有效操作可用性。
- 不支持历史时说明原因，普通 filesystem 存储仍可使用。
- Workspace 编辑呈现来源、校验、差异和修订冲突；发现审核不静默改写记录。
- 键盘与手柄流程在对话框、筛选和导航中保持可见、可预测的焦点。
- 进度与取消反映真实操作状态，包括部分结果和不支持暂停/续接的情况。
- 重新连接仍在运行的任务主机后恢复状态，不创建重复操作，并明确支持的生命周期。
- 完成通知提供显式操作，不自动启动游戏或抢占焦点。
- 减少动态效果与缺图状态仍可使用；派生封面可以与来源区分。

## 生命周期边界

使用 core 只读目录/激活 observable 与诊断，区分已声明、inactive、blocked、failed、active 实现。展示 `restart-service-required`，不暗示自动或仅重载 Extension。[ADR 0006](../adr/0006-SERVICE-OWNERSHIP-AND-LAZY-ACTIVATION.md)提供生命周期 API，marketplace/下载和安装 UI 仍待实现。

## 发现与稳健性后续

目录 list/status/refresh 与结构化阶段诊断已实现。未来 UI 必须展示清理不完整和重启要求，不暗示代码已被杀死；安装/marketplace UI、持久启停及独立 host 控制仍是独立工作。证据及实施触发条件见 [ADR 0007](../adr/0007-EXTENSION-DISCOVERY-AND-LOAD-ROBUSTNESS.md)和[源码对照](../007-EXTENSION-SYSTEM-COMPARISON.md)。

CLI 现已提供 Workspace 初始化、审核单记录编辑、游戏库查询与设置解释；审核及恢复边界见 [ADR 0008](../adr/0008-WORKSPACE-MANAGEMENT.md)和[管理指南](../008-WORKSPACE-MANAGEMENT.md)。未来图形 UI 复用这些服务，区分预览/apply 不可用、unchanged、conflict、recovery-required，不暗示通用撤销。
