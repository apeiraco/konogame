# ADR 0011: Effect contracts, composition and lifetime

Status: Accepted, 2026-10-26.

## Context

Asynchronous Ports, stream ownership, dynamic Extension activation and writer recovery need one typed dependency/error/concurrency model. The previous explicit injection-js/RxJS design and application handle split ownership across providers, callbacks, Promises and custom cancellation. The requested full Effect migration deliberately breaks those APIs during the local experimental phase.

## Decision

Pin `effect`, `@effect/platform-node` and `@effect/vitest` to 4.0.6 once, in the default pnpm catalog. Use the actual `Context.Service` API. Owner tags and native Layers replace InjectionToken/provider arrays, custom Env/application contexts and duplicate service registries. Keep stateful algorithms in classes and pure schemas/values/parsers/rules pure.

Side-effecting Ports, Adapters and workflows return `Effect<Success, Error, Requirements>` with owner tagged errors. Artifact file collections and bytes are native Streams, opened on demand under Scope, without whole-asset buffering. Promise conversion and runMain/runPromise/framework FiberSet bridging belong only to real process, external framework/import/I/O and test boundaries. Business Ports carry no AbortSignal.

`composeApplication` and `composeLocalApplication` return complete native Layers. Root composition selects no Extensions; local composition selects bundled pure `/providers` sources and explicitly configured installed roots. Owner Layer overrides enter the fixed root graph. Acquisition prepares only in catalog-only mode; normal acquisition finishes startup before exposing application services. Business workflows stay in application and never import composition. Core owns generic `LocationBehaviorService`/`LOCATION_BEHAVIOR`.

Core root assembly remains one native `Layer.effectContext`. Its accessor has type `Effect<Context<InfrastructureServices>, InfrastructureError>` and polls a Deferred: access during construction fails immediately with the Providers-phase error instead of waiting or exposing a partially assigned context. The Deferred is completed only after the full service graph and lifetime finalizer are installed; later reads share that fixed context and root overrides. Requirements are erased only at the validated dynamic Extension execution boundary. See [core assembly](../../../packages/infrastructure/src/providers.ts) and [root-access tests](../../../packages/infrastructure/src/__tests__/providers.test.ts).

ExtensionModule supplies an optional native layer (or activation-context Layer factory) and Effect activate. Each generation owns a Scope and built service context; explicit root overrides win. Only declared active dependency contexts are accessible through dependencyServices. Strict declaration validation, atomic dual-registry catalog commits, lazy binding, staged implementation publication, per-generation completion/failure caching, missing/version/cycle re-evaluation, replay/refresh ownership and restart-after-load constraints remain. Private PubSub exposes read-only Stream observations and snapshots; observers do not synchronize registries.

Cooperative custom Extension cleanup should use [addLifetimeFinalizer](../../../packages/infrastructure/src/services.ts), which registers a native Scope finalizer and applies interruptible individual/remaining-total budgets without another executor; ordinary acquireRelease/addFinalizer and library releases retain native Scope interruption protection, so 1s/5s is not a universal hard deadline and interruption cannot establish that handles have closed.

Native Scope/Fiber/Deferred/Clock own cleanup, cancellation and deadlines. Defaults remain discovery/load 15s, activation 30s, total shutdown 5s and individual cleanup 1s. These budgets are cooperative: synchronous/non-yielding code, deliberately uninterruptible effects and uncancellable external operations may outlast them. No custom detached cleanup scheduler, fiber-internal workaround or in-process sandbox is introduced.

Filesystem save publication uses an internal Windows-only native rename EPERM retry policy: at most five total attempts, cancellable 25/50/100/200ms backoffs (375ms total), and a Clock-based 500ms soft budget measured from helper entry that constrains only later retries, checked after waiting/target inspection and before a later rename. The first attempt is always allowed, including after a slow initial lstat. Each native rename is narrowly masked and awaited to settle, so it may exceed that budget. Each attempt lstat-checks the target; existing targets fail immediately and non-ENOENT inspection errors do not retry. Exhaustion retains SaveError/native cause; no Artifact input replay, new ID, recopy or target deletion occurs, and failure cleanup removes only owned staging. The precheck has a TOCTOU window and is not atomic no-replace or general transactions. The observed EPERM root cause is unknown. See the [publication helper](../../../extensions/filesystem/src/save-store/publication.ts).

Workspace read/rename/import/initialize/edit/recovery preserve Schema 4, TOML/layout/comments, UUIDv7/uniformName/unicode-fs-v1, source and Location invariants, fresh root/revision/evidence/binding checks and targeted journals. Writer locks are scoped; only owned locks are released. A minimal native filesystem publication may mask interruption until that single operation completes. Recovery restores approved metadata without Location execution. This is not general transactions or atomic directory publication.

Interruption remains Interrupt. In Effect 4.0.6, nested acquireUseRelease interrupted by real Fiber.interrupt can omit an additional finalizer failure from the outer Cause. Recovery-required rename/lock finalizers first emit structured Effect Logger diagnostics; CLI/daemon use Logger.LogToStderr to preserve JSON stdout. Ordinary errors retain typed channels/results. Journals and logs are essential recovery evidence; complete cleanup Cause propagation is not promised for every interruption.

Contract protocol becomes `0.2.0` with `>=0.2.0 <0.3.0` because Port/Artifact/Extension APIs break. Shared core and independent Extension release versions remain `0.1.0-alpha.0`. `konogame-metadata.toml` remains canonical and release sync generates projections. Schema 4 and `extension.package.1` data layout are unchanged. No historical migration or old Promise/DI compatibility facade is added.

Tests use owner Layer replacements, `@effect/vitest` and TestClock where effects/time matter; pure tests remain pure. Unit/integration/e2e classification, real built program workflows, owner-port or real-directory file tests, temp/tests, Turbo prerequisites and source export conditions remain intact. Full repository validation is required independently of focused package passes; this decision does not assert a completed full check.

Effect behavior tests return Effects through `@effect/vitest` `it.effect`, using TestClock for controlled time and real Fiber/Scope cancellation. Native filesystem and live-clock integration tests use `it.live`; do not freeze their clock by default. Test known failures with `Effect.flip`, Exit/Cause and owner tags/issues, without per-test runPromise wrappers. Pure schema/parser/value/type tests remain ordinary Vitest tests; do not wrap pure work in Effect for uniformity. Promise bridges remain only at actual external I/O, framework/process and fixture boundaries; physical fixture cleanup retains one Scope or hook owner.

Known schema and rule refusals use structured owner tags/issues; applicationRule/configurationRule preserve recognized objects as Fail, while unexpected trusted-code throws remain Die. UnexpectedBoundaryError is reserved for explicitly identified third-party boundaries and does not make arbitrary Extension/schema behavior exhaustive. WorkspaceConfigurationError includes known schema/rule errors, filesystem/configuration-input/writer conflict and recovery data protocols, explicit boundary errors and fresh-admission LocationError; implementation classes and native code/cause remain with their owners. Cause-aware result handling never converts Die/Interrupt to an ordinary workflow status. See the [development error guide](../004-DEVELOPMENT.md#typed-rule-failures-and-defects).

## Consequences and supersession

ADRs 0004, 0006, 0007 and 0009 retain their original historical text. This ADR supersedes their DI, asynchronous observation, composition handle and lifetime mechanics; their domain boundaries and package ownership remain. Schema/Location/binding/admission/recovery rules from ADRs 0002, 0005, 0008 and test/task-graph rules from ADR 0010 remain current.
