# ADR 0008: Workspace management and library maintenance

Status: accepted, 2026-10-18. Extends the narrow metadata workflows in [ADR 0002](0002-WORKSPACE-TOML-AND-TOOLING.md), retaining [ADR 0005](0005-LOCATION-REGISTRIES-AND-CORE-PERSISTENCE.md)'s Location and core persistence ownership. Exact commands are in the [management guide](../008-WORKSPACE-MANAGEMENT.md).

## Decision

Add `initialize`, `recover-initialize`, `edit`, `recover-edit` to the existing Workspace configuration Port, with separate matching Features/Capabilities. Domain `applyConfigurationEdit` computes a valid single-record result and semantic differences from explicit intents: `metadata.replace`, `settings.replace`, `host.create`, `host.roots.replace`, `host.sources.replace`. Application management coordinates bindings and review; core configuration owns TOML/I/O/journals; CLI handles parameters, confirmation and presentation. No new provider registry or arbitrary patch system is introduced.

Initialize only in a caller-selected existing root. Exclusively reserve `.konogame`, stage a fixed bounded file set, publish `.gitignore` and a directory-layout initial Host without replacement, and publish `workspace.toml` last. History is disabled. Workspace/Host UUIDv7 IDs are distinct and supplied by the application; Host defaults/roots/sources/overrides begin empty. `.konogame/.gitignore` excludes local/cache/recovery without touching the root ignore file. A journal and operation receipt support targeted recovery; an existing configuration directory is a conflict, and missing recovery evidence requires manual inspection. Directory rename is not used to claim portable no-overwrite atomic initialization.

Edit previews are strict `workspace-edit-preview.1` values containing root/Workspace identity, expected raw revision, operation identity, Adapter identity, intent, differences, read/apply plans and digest. Preview is read-only, including when a read-only Adapter cannot apply. Apply independently anchors the caller root, strictly validates the preview, rereads and rebuilds the review, and resolves the write capability before persistence. The digest detects changes, not an authenticated authorization signature. Stale reviews require new previews; no automatic replay is promised.

Metadata projections edit only Workspace name, Game title/edition and Host label. UUID, uniformName, relationships, Location, external references and launch entries remain outside these projections. UniformName uses rename. Raw Game metadata replacement omits edition to remove it; CLI title-only preserves edition, with explicit unset for removal. Settings replace one whole persistent layer: omission inherits, clear explicitly removes an inherited selection, and an empty arguments array is an explicit value. Empty Host/Game settings remove the override. Convenience flags may preserve current unrelated values when constructing the full intent. Built-in/caller layers are not persisted.

Host source deletion or kind change cannot invalidate an Installation reference. Status may return to planned while references remain. Roots remain Adapter context, never scan permission or core path interpretation. Library list/show joins identities, Host/source declarations and original Location availability. Settings explain returns all seven layers, effective values/origins, explicit clears and per-Feature compatibility; binding evaluation does not execute the asset operation. Explain derives the Host from an installation-only selection and rejects explicit contradictions; Location status remains independent from generic Feature binding, so unknown Location does not disable Artifact storage or metadata editing. The existing inspect selection contract is unchanged.

Initialization/edit share writer coordination and pending-operation gates with rename/import. AST range editing preserves unrelated TOML bytes/comments, newline style and existing layout. Edited records remain bounded to 1 MiB UTF-8; management journals to 16 MiB. Existing-record writes use a single-file replacement after final content checks; new Host files publish exclusively. A targeted edit journal/receipt validates intent, before/after content, revision and hashes for forward completion. External-editor races remain possible at the last check/replacement boundary; external changes stop recovery. This is not general transactions or arbitrary rollback. Metadata edit/recovery does not execute Location resources or depend on Location registration/history. An accepted unchanged result preserves record bytes but consumes operation identity and may write a coordination receipt; the same request can retry unchanged, while a different payload/revision under the same operation ID conflicts. Coordination/recovery files may still be touched.

## Consequences and scope

Users can initialize, declare Hosts/sources, discover and admit games, query the library, review supported edits and explain their effects without hand-authoring all records or requiring Git/daemon. JSON/non-TTY writes require explicit confirmation; cancellation does not write. Schema 4 and release versions remain unchanged, with no migration scaffolding or private data in public examples. Arbitrary edits/deletion, installation identity/Location changes, launch, configuration history and asset backup/restore remain future work with separate review and recovery contracts.
